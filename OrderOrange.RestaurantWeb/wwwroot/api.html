Quick start

Base URL https://api.orderorange.com. Three calls: sign in, read your restaurant, write an order. Every example on this page was run against a real store.

1Sign in, keep the tokenPOST your partner login; the answer carries a JWT that lasts 12 hours, or 30 days with remember.
2Read with GETAdd Authorization: Bearer …. Everything is scoped to the store the token belongs to.
3Write with POST or PUTSend JSON with Content-Type: application/json. Most writes answer 204; creations answer the created object.

Authentication

The API uses the same logins as the partner app. A token is a store: it carries the restaurant it works in, the role, and the permissions.

Getting a token

MethodRouteNeedsSendsReturns
POSTapi/auth/loginno token{ "email": "login", "password": "…", "remember": true }LoginResponse — token, userId, restaurantId, storeRole, perms
POSTapi/auth/switch-store/{restaurantId}token · owner—LoginResponse with a new token for another business you own or work in
GETapi/restaurants/my-storestoken · owner—the businesses this login may switch to
Lifetime. 12 hours, or 30 days with remember: true. There is no refresh endpoint: sign in again when you get 401. Keep the token server-side; never ship it inside a browser page or a mobile app.

Roles and permissions

Owners can do everything in their store. A team member gets a storeRole (owner, manager, cashier, kitchen, waiter) or a custom role, and the token then carries a perms list. Each write endpoint names the permission it needs; the reference below shows it as token · menu. A call without the permission answers 403 { "code": "perm.denied" }.

Recommended for integrations: create a team member for the integration in Team, give it a custom role with only the permissions it needs (for accounting: reports; for a CRM: customers; for a kitchen screen: orders), and sign that member in from your server.

All permission keys: pos · orders · orders.cancel · tables · tables.view · chat.guest · chat.team · menu · menu.view · inventory · inventory.view · suppliers · suppliers.view · invoice.cancel · invoice.edit · reports · bills · payments · payroll · discounts · contracts · reservations · deliveries · customers · customers.view · staff · settings · team · surveys · calendar · support

Conventions

JSON, camelCaseRequests and responses are JSON; property names are camelCase (menuItemId). Unknown properties are ignored.
Money and taxDecimals in Omani rial with three places (4.500). Tax is Oman VAT, taxPercent 5 by default, and is on every order and invoice.
DatesISO 8601 in the store’s local time, Oman (UTC+4): 2026-09-18T01:05:48. Send the same shape.
LanguagesNames come as dictionaries keyed by language code (names.ar), fourteen codes. Ask for one language with ?lang=ar on the menu.
PagingLists that can grow take skip and take (default 25 to 100). Reports take period or from and to dates.
Status codes200 with a body · 204 done, no body · 400 validation · 401 sign in again · 403 permission · 404 not yours or gone · 429 slow down.
Ids are stableStore, item, order and customer ids never change; keep them as external keys. The order number (MF-755259) is what people see on receipts.
Store scopePartner endpoints never take a store id: the token decides. To work on a second business, call switch-store and use the new token.

Order lifecycle

Every order walks the same road; each step is one POST and is written into history[] with who did it.

0Pending→1Accepted→2Preparing→3Ready→4PickedUp→5OnTheWay→6Delivered
8Rejectedfrom Pending, with a reason the guest sees
7Cancelledby the guest or the store, with an optional reason

Counter sales and dine-in orders end at Ready and are settled with paid; deliveries your own people take out go through courier and self-delivered. A rejected or cancelled order stays in history and in the cancelled-invoices feed.

Connect a CRM or accounting software

There is no separate integration product: the API is the integration. Four patterns cover almost everything; each one below is a working sketch.

Accounting: every invoice, nightly

Zoho Books, QuickBooks, Xero, Odoo, Sage or an Excel-based bookkeeper. Read one day of invoices with lines and tax and create them on the other side; use the invoice number as the idempotency key so a rerun never duplicates.

python · nightly job
# Nightly: push yesterday's invoices into the accounting system (Zoho Books, QuickBooks, Odoo, Xero…)
import requests, datetime
API = "https://api.orderorange.com"
s = requests.Session()
s.headers["Authorization"] = "Bearer " + s.post(f"{API}/api/auth/login",
    json={"email": "sync-user", "password": "…", "remember": True}).json()["token"]

day = (datetime.date.today() - datetime.timedelta(days=1)).isoformat()
report = s.get(f"{API}/api/invoices/daily", params={"date": day}).json()
for row in report["rows"]:                       # one row per invoice
    inv = s.get(f"{API}/api/invoices/{row['id']}").json()   # lines, tax, payment
    accounting.create_invoice(
        number   = inv["number"],                # MF-755259 — use it as the idempotency key
        date     = inv["placedAt"][:10],
        customer = inv["customerName"] or "Walk-in",
        lines    = [(l["name"], l["quantity"], l["unitPrice"]) for l in inv["items"]],
        tax_rate = inv["taxPercent"],            # Oman VAT, 5 %
        total    = inv["total"],
        paid     = inv["isPaid"],
    )
# Cancelled and edited invoices have their own feeds:
#   GET /api/invoices/cancelled   GET /api/invoices/edits

Prefer files? POST api/export/xlsx returns the same Excel sheet the app’s Excel button makes, for any report.

CRM: customers both ways

HubSpot, Zoho CRM, Salesforce, Bitrix24 or your own. Customer cards carry name, phone, address, order count and last visit; a lead created in the CRM becomes a store customer with one POST.

javascript
// Keep the CRM in step with the store's customer list, both ways.
const API = "https://api.orderorange.com";
const auth = { Authorization: `Bearer ${token}` };

// OrderOrange → CRM: every customer, with order count and last visit
const customers = await fetch(`${API}/api/storecustomers?take=1000`, { headers: auth }).then(r => r.json());
for (const c of customers)
  await crm.upsertContact({ externalId: `oo-${c.id}`, name: c.name, phone: c.phone,
                            address: c.address, orders: c.orderCount, lastOrderAt: c.lastOrderAt });

// CRM → OrderOrange: a new lead becomes a store customer
await fetch(`${API}/api/storecustomers`, {

Orders into an ERP or a kitchen screen

No webhooks yet, so poll the live board every few seconds; it is small and fast. New orders are status 0; accept them from your side if you want the board and your system to agree.

javascript · poll the board
// A kitchen screen or an ERP that wants every new order: poll the board.
let seen = new Set();
setInterval(async () => {
  const board = await fetch(`${API}/api/orders/restaurant/board`, { headers: auth }).then(r => r.json());
  for (const o of board.filter(o => o.status === 0 && !seen.has(o.id))) {   // 0 = Pending
    seen.add(o.id);
    await erp.createSalesOrder(o);                                            // your side
    await fetch(`${API}/api/orders/${o.id}/accept`, { method: "POST", headers: auth });
  }
}, 5000);
